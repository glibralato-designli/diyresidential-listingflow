Component proof sheet

Section 11 of the spec. These render through the app's real functions (living-card.js, nav.js) with swapped-in demo state — not restyled copies.

Living card — all states

Skeleton → partial → photographed → complete, plus the <1280 band variant. Non-interactive: no hover, no cursor change, no elevation change.

Act cover & milestone

Exactly five elements on the cover: act number, title (≤4 words), one line (≤14 words), three chips, one button. No duration, ever.

Why-line — four variants, plus the comparison strip

The critical constraint: good-to-know and value-prompt occupy the same position and size as the error line and the muted helper — a compliment must not look like a warning.

Act-scoped navigation

One rendering showing every state at once: a done act (collapsed, green check), the current act (expanded, with done/active/todo step rows), and upcoming acts (single greyed row, one-line promise, no padlock).

QuestionCard + Toggle Group

Confirmed real components (node 5663:54799 / 5663:54803 / 5663:54815) — one bordered card per question, label + help-circle header, a pill-shaped segmented control below. Selected = pale amber fill + bold amber-brown text; unselected = transparent + bold near-black text, both weights equal.

Choice card grid

E1's property-type grid. 3×2, icon 32–40px above the label, no subtitle. Selected state uses the wizard's amber accent, not the brand green.

Prefill confirmation control — all states

Unconfirmed → confirmed / corrected, plus the nothing-was-prefilled case (coverage varies by address).

"I'm not sure" / "Unknown" — both forms

An explicit option on paced screens; inline on every row on dense screens. Never blocks continue.
